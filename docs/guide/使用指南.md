# 使用指南

按一条真实业务链走一遍：管理员建节点 → 建用户 → 发卡密 → 用户兑换拿订阅 → 流量/通知日常运营。所有能力以源码路由为准（`server/internal/handler/router.go`），本页是操作视角的串联。

## 管理端（dash）

登录后左侧按业务域分页：

- **节点（Nodes）**：池内节点的生命周期——建节点（名称/角色 entry|landing|both/方向出海|回国/线路类型/区域）、改带宽画像、下发配置（config.push 热生效）、进程操作与升级、看流量账。均衡系数（负载/成本/优质线权重）在落地分配页可改，缺省 0.5/0.3/0.2。
- **落地与池（Landings/Pool）**：落地分配与池摘挂——手动挂起/恢复/待命，或交给自动循环（边缘探测 → 复审 → 摘挂 → 补位）。
- **用户（Users）**：建用户（配额/到期）、重置订阅令牌、看用户流量账；用户模板页定义新用户缺省配额与到期。
- **卡密（Cards）**：按批次生成卡密（add_quota 加流量 / extend_days 续时长，可定价在线售）、导出 CSV 发放、禁用单个码、删批次（DB 级联连带名下码）。
- **通知（Notifications）**：发公告（扇出全部启用用户，禁用用户不收）、看全量站内信、按类型清理。
- **成本（Cost）**：成本核算、参考库价格比对、价格关注条件、晚间汇总。
- **对账（Reconcile）**：支付流水三账对齐视图（订单/流水/发放按 order_no 串联，缺环节一眼看出）；订单详情与退款流转（仅 paid → refunded）。
- **代理（Distributors）**：分销代理建号/佣金比例/账目流水与结算打款（手动落账）。
- **设置（Settings）**：2FA 绑定、登录日志、运行日志、通知通道测试。

## 用户端（panel）

用户凭**订阅令牌**登录（管理员建用户后发订阅地址，令牌即身份）：

- **概览（Home）**：剩余流量/到期时间/通知偏好卡（到期提醒、流量预警双开关 + 个人预警阈值 1-100%）；
- **兑换（Redeem）**：输入卡密一键兑换，成功即到账（加流量或续时长），同码重复兑换被唯一约束挡下；
- **订单（Orders）**：购买记录，按来源筛选（卡密兑换 / USDT 在线支付）；
- **通知（Notifications）**：站内信列表，未读高亮、单条已读、全部已读；公告随扇出到达；
- 订阅地址不变——换节点、换线路对用户透明（服务端按池分配自动重指）。

## 订阅与流量

- 订阅端点 `GET /sub/<token>`：按 token 限频（30 次/分）；未命中 token/停用用户按 IP 记（20 次锁 15 分钟）；
- 订阅内容随池动态：节点被摘挂、换落地、换传输，用户下次拉订阅即得新配置；
- 流量账按小时落账（agent 心跳上报，dashboard 用户页可查）。

## 日常运营循环

1. **看板**：健康自检 `/api/health` + dash 概览（在线 agent 数、备份新鲜度）；
2. **告警**：区域/运营商故障迁移、判封摘挂、证书进续期窗口、池摘挂、成本超阈、备份失败——事件全走 outbox 投递，dash 事件页三态计数（pending/delivered/failed），死信可人工重投；
3. **例行触达**：到期提醒与流量预警按扫描周期自动发（同日同用户至多一条）、月账单与域名清单定期邮件（经 Herald 分发）；
4. **备份**：每日落档滚动保留，恢复流程见[部署指南](/deploy/部署指南)。

## 与 Herald 对接

面板事件外发（告警 + 用户触达）统一投 `{FERRY_HERALD_URL}/events`，Bearer Token 鉴权，异步回投通道分发回执。事件清单、去重语义与对接实录见[告警通道设计](/design/告警通道设计)与[Herald 对接实录](/herald-对接实录)。
