# FAQ

## 登录与账号

**首次管理员账号怎么来？**
`ferry.env` 配 `FERRY_ADMIN_PASSWORD`（用户名缺省 `admin`），首启且库内无管理员时自动建号；已有管理员则忽略该变量，不会覆盖密码。建议建号后立即绑定 2FA 并把变量从 env 移除。

**管理员密码忘了怎么办？**
`FERRY_ADMIN_PASSWORD` 只在首启建号生效，不能用来重置已有账号。路径二选一：dash 内用其他管理员改密（多管理员时），或从最近备份恢复后用已知凭据登录。登录失败有审计（「设置 → 登录日志」）。

**2FA 恢复码丢了、TOTP 设备也没了？**
恢复码是最后一把钥匙，绑定时要离线保存。两者都丢只能走备份恢复（备份在 2FA 绑定前的批次）。这也是备份滚动保留存在的意义之一。

## 存储与备份

**能切 Postgres 吗？**
能。`--profile postgres` 起 compose，`FERRY_DB_DRIVER=postgres` + `FERRY_DB_DSN` 指向实例（`ferry.env.example` 有注释模板）。缺省 sqlite 对单机小内存定位已够。

**`FERRY_SECRET_KEY` 换了会怎样？**
用它加密的机密（云凭证等）解不开、旧备份无法用 `backup-decrypt` 解密。该密钥必须一次设定长期稳定；轮换等于全部机密重录+旧档作废。

**备份在哪、怎么验证没坏？**
本地落档 `FERRY_BACKUP_DIR`（每日 cron、滚动保留）；`/api/health` 的 `backup` 检查项超 48h 未备份会置 `degraded`。恢复用 `deploy/restore.sh`，六步含健康冒烟，失败明确报错可复跑。

## 节点与订阅

**agent 装完不上线？**
按序查三处：`journalctl -u ferry-agent -f`（连接报错会打在这里）→ 面板域名反代是否放行 `/agent/ws`（Caddy 模板四路径：`/api`、`/sub`、`/agent`、`/feed.xml`）→ 节点令牌是否与面板一致。上线后 `/api/health` 的 `agents_online` 应 +1。

**用户拉订阅 404？**
令牌错或用户被停用。注意保护机制：同一 IP 连续 20 次未命中会锁 15 分钟（防枚举），测试时别拿错令牌连打。

**节点被摘挂了用户会断吗？**
自动换线是设计目标：探测判病 → 复审 → 摘挂 → 池补位，用户订阅地址不变，下次拉订阅即指向新落地。订阅里还有断联容灾注释行（管理员可手动置断联态提示）。

**QUIC sidecar 什么时候要装？**
只有传输插件选 `quic` 才需要（`--quic`）。不用 QUIC 的部署不装——agent 主程序不携带 quic-go，尺寸门禁也不量它。

## 支付与卡密

**卡密兑换报「兑换失败」不区分原因？**
有意的：不区分「码不存在/已用/禁用」防爆破探测。真实原因看 dash 卡密页（fail_count 计数、禁用态）与登录/操作日志。

**USDT 在线支付怎么开？**
需外部 epusdt 服务，`payments/epusdt` 插件直读 `FERRY_EPUSDT_URL/TOKEN/NOTIFY_URL`（面板 env 不经手）。没配在线支付时卡密兑换通道完整可用。

**退款怎么操作？**
dash 对账页订单详情 → 退款（仅 `paid` 可退，退后置 `refunded`）。对账口径：paid 订单 ⇔ ≥1 条流水 ⇔ ≥1 条发放。

## 其他

**面板只监听一个口，内部接口怎么隔离？**
单 `FERRY_ADDR` 同引擎监听，内部接口（事件回执等）靠部署侧网络边界隔离（内网/防火墙），不设第二监听口。

**公告/站内信会发邮件吗？**
站内信必达；站外投递（邮件/TG）走 Herald 分发，面板只保证事件投出到 `{FERRY_HERALD_URL}`。未配 Herald 时站内信照常、外发静默跳过。

**部署者合规责任？**
ferry 是代理集群管理工具，部署与运营的合规责任在部署者，见[合规定位声明](/design/合规定位声明)。
