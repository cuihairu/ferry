# 部署指南

ferry 面板 = 一个服务端二进制 + 两个静态前端（dash 管理端 / panel 用户端）+ 可选 Postgres，容器化部署在 `deploy/` 下；agent 装在节点机上，不经 compose。

## Docker Compose（推荐路径）

```sh
cp deploy/ferry.env.example deploy/ferry.env   # 按需修改
docker compose --env-file deploy/ferry.env -f deploy/docker-compose.yml up -d --build
```

三个容器：

- `ferry-server`：服务端单二进制，默认 sqlite 落卷 `/data`；
- `ferry-dash`：Caddy 托管 dash/panel 静态产物，并反代 `/api`、`/sub`、`/agent`、`/feed.xml` 到服务端（四条路径缺一不可，agent 连 `/agent/ws` 走这里）；
- `ferry-postgres`：可选（`--profile postgres` 启用），切换存储见 `ferry.env.example` 注释。

## 关键环境变量

全集见 `deploy/ferry.env.example` 与 `server/internal/config/config.go`，首启前必须看清的几张：

| 变量 | 作用 | 注意 |
| --- | --- | --- |
| `FERRY_ADDR` | 服务监听地址（缺省 `:8080`） | 单监听口，internal 接口同引擎，网络隔离靠部署侧 |
| `FERRY_BASE_URL` | 对外基准 URL | 订阅地址、回调按它拼 |
| `FERRY_ADMIN_USER` / `FERRY_ADMIN_PASSWORD` | 首启建号 | 库内无管理员时才建号；已有管理员则忽略，不覆盖密码 |
| `FERRY_SECRET_KEY` | 机密加密根密钥（32 字节） | 2FA、云凭证录入、备份加密都依赖它；**必须稳定**，换了旧备份解不开 |
| `FERRY_DB_DRIVER` / `FERRY_DB_DSN` | 存储选择 | 缺省 sqlite；`postgres` + DSN 切库 |
| `FERRY_HERALD_URL` / `FERRY_HERALD_TOKEN` | Herald 对接 | 空 = 外发通道禁用，不阻断主流程 |
| `FERRY_SUPPORT_URL` / `FERRY_SUPPORT_SERVICE_KEY` | 外部客服（servify）对接 | 空 = 面板客服入口关闭（零外呼零组件）；key 是 servify 签发的 service API key，只在服务端使用 |
| `FERRY_BACKUP_*` | 周期备份 | 目录/cron/保留份数；S3 外发默认关，`FERRY_BACKUP_S3_ENABLED=1` 显式开 |

## 管理员首启

1. `ferry.env` 配好 `FERRY_ADMIN_PASSWORD`（可选 `FERRY_ADMIN_USER`，缺省 `admin`）后启动；
2. 浏览器打开面板域名 → dash 登录页用该账号登录（JWT）；
3. 进「设置 → 两步验证」绑定 TOTP（需先配 `FERRY_SECRET_KEY`），之后登录再验 6 位动态码/恢复码；
4. 密码修改在 dash 设置页完成；`FERRY_ADMIN_PASSWORD` 之后从 env 里去掉即可（仅首启语义）。

登录审计在「设置 → 登录日志」（成功/失败、IP、2FA 路径，P1 安全批）。

## agent 节点安装

节点机 root 执行（面板机上 `--register` 可顺手建节点拿令牌）：

```sh
deploy/agent-install.sh --panel https://panel.example.com --token <节点令牌>
# 令牌还没建：
deploy/agent-install.sh --panel https://panel.example.com \
  --register hk1 --address hk1.example.com --port 443 --protocol vless
```

脚本做四件事：下载发布包并校验 sha256（`--binary` 可离线装）→ 装到 `/usr/local/bin/ferry-agent` → 写 `/etc/ferry/agent.json`（已存在则保留）→ 装 systemd 服务并启动。日志看 `journalctl -u ferry-agent -f`。

- `meta.bw_up_mbps` / `meta.bw_down_mbps` 是 agent 配置必填项（脚本 `--bw-up/--bw-down` 写入，默认 100/100，面板节点页可改）；
- `--node-role entry|landing|both` 写集群角色（不写默认 landing）。

relay 数据面与 QUIC sidecar 的安装参数（`--role relay`、`--relay-tunnel ssh|quic`、`--quic`）见仓库 `deploy/README.md` 对应节。

## mTLS（可选）

面板机自签 CA 并按节点签发客户端证书，CA 私钥只留面板机：

```sh
deploy/mtls-ca.sh init
deploy/mtls-ca.sh issue hk1 825   # 签发 hk1.crt/.key
# 安装时传三件套启用双因子
deploy/agent-install.sh --panel ... --token ... \
  --ca deploy/mtls/ca.crt --cert deploy/mtls/hk1.crt --key deploy/mtls/hk1.key
```

## 备份与恢复

- 周期备份默认开：每日落档 `FERRY_BACKUP_DIR`，滚动保留 `FERRY_BACKUP_KEEP` 份，失败走告警通道不静默；
- S3 兼容端点外发为显式开关（`FERRY_BACKUP_S3_ENABLED=1` + 四个 `FERRY_BACKUP_S3_*` 值），失败告警且本地档保留；
- 换机恢复一条命令（解密→导入→证书→启动→健康冒烟六步）：

```sh
deploy/restore.sh --backup ferry-backup-*.db.enc --data-dir /data \
  --ferry-bin /usr/local/bin/ferry-server --key "$FERRY_SECRET_KEY" \
  --start-cmd "systemctl restart ferry" --health-url http://127.0.0.1:8080/api/health
```

换机迁移完整 runbook（DNS 切换、agent 重连核对、回滚）见仓库 `deploy/MIGRATION-RUNBOOK.md`。

## 健康自检

`GET /api/health` 返回 `status`（`ok`/`degraded`）与三项检查：`db_writable`、`agents_online`（在线 agent 数）、`backup` 新鲜度。`degraded` 仍返回 200（探活方不误杀），异常项如实上报。Herald 通道健康不单独探测，看 dash 事件页三态计数。

## 升级

拉新镜像重建即可（数据在卷里）：`docker compose ... up -d --build`。agent 自带升级链路（面板节点页可触发），ferry-quic sidecar 随发布包另行下载。数据库迁移由服务端启动时 AutoMigrate 增量完成。
