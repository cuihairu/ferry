# 面板可用性设计

目标：面板是小内存 VPS 上的单点——备份可恢复、迁移可执行、故障语义写清楚（挂了会怎样、什么照常跑）。

## 1. 故障语义（先说清楚面板挂了会怎样）

```
面板不可达时：
  ✅ 已下发订阅照常可用（客户端持有订阅缓存与节点直连信息）
  ✅ 节点代理进程照常跑（agent 本地自治：进程拉起/退避不依赖面板）
  ✅ 隧道与用户流量不受影响
  ❌ 管理面失联：无新配置下发、无摘挂/换线决策
  ❌ 心跳上报失败（agent 本地重试缓存，恢复后补报）
  ❌ 购买/兑换/注册不可用（用户侧表现=服务正常、购买暂停）
  ◐ 告警经 Herald 的本地 outbox 攒着，恢复后补投（见《告警通道设计》§4）
```

- **结论**：面板挂 = 管理与商业化暂停，不是服务中断。这一定义决定 RTO 目标可以宽松（小时级），备份链路按此设计。

## 2. 备份

### 2.1 备什么

| 内容 | 方式 |
| --- | --- |
| 数据库（用户/节点/流量/三账） | SQLite：`.backup`（WAL 在线备份）；PG：`pg_dump` |
| 节点配置快照 | 随库（nodes.config / node_configs） |
| mTLS CA 与证书 | 文件目录一并打包 |
| 机密密文 | 随库（密文可备；**主密钥不进备份包**，另行保管） |

### 2.2 备份策略

- 周期备份（默认每日）：面板本地保留 N 份（默认 7），滚动覆盖；
- **外发位**：备份完成后可推对象存储/S3 兼容端点（已接入 S3 兼容端点 SigV4 PUT，默认关闭），推失败告警（`backup_failed` 经 Herald）；
- 备份文件含机密表 → 打包加密（secret_store 派生钥），对齐《安全设计》§3；
- 手动备份：dash 一键触发（对齐 P1-6 备份导出端点）。

**落地口径（2026-10-08 P1 备份批）**：`server/internal/backup`——周期调度 `backup.Loop`（60s tick 轮询 cron Next，装配沿 `FERRY_*_SEC` 惯例）；快照=SQLite `VACUUM INTO` 在线一致性备份（`.backup` 同义口径，WAL 已合并，与手动端点共用 `backup.Snapshot`）；配置了主密钥即 `secret.EncryptBytes` 打包加密（派生钥 AES-256-GCM，文件格式=版本字节+nonce+密文，主密钥不进备份包；未配主密钥落明文 `.db`——该部署库内本无机密明文，无泄密增量）；滚动保留 `FERRY_BACKUP_KEEP` 份（manual/scheduled 不分，超窗连文件带 `backups` 行删，窗口内文件丢失的幽灵行同清）。调度 `FERRY_BACKUP_CRON`：`daily`/`HH:MM` 别名 + 标准 5 段（robfig/cron v3，MIT），缺省每日，解析失败回退每日并日志说明。失败经 `backup_failed` 告警（本地按日自查重，方言不支持等持续故障每日至多一条，不静默）；postgres/mysql 本批未支持（走各自备份设施，周期备份按日告警而非静默跳过）。**外发位已接真实外发（2026-10-09 外发批）**：默认关闭、显式 `FERRY_BACKUP_S3_ENABLED=1` 才视为开启并注入 `backup.S3Uploader`——stdlib 手写 AWS SigV4 单对象 PUT（path-style `{endpoint}/{bucket}/{key}`，payload 参与签名，零新依赖）；每次外发日志明示数据范围=备份目录全部落档文件，上传成功才置 `uploaded=1`，失败走 `backup_failed` 告警（title=备份外发失败，与快照失败共用按日去重窗口）且本地档保留；manual 手动落档不走外发。

## 3. 一键恢复

```
新机/同机恢复流程（脚本 deploy/restore.sh 已落地，2026-10-08 恢复批；迁移操作实例见 deploy/MIGRATION-RUNBOOK.md）：
  ① 部署 ferry（同版本或更高）
  ② 注入 FERRY_SECRET_KEY（主密钥）+ 解密备份包（ferry-server backup-decrypt 子命令，openssl 无 AES-GCM 能力）
  ③ 导入数据库（SQLite 留底+原子覆盖 / pg_restore --clean，档须 pg_dump -Fc 自备）
  ④ 恢复证书目录（--cert-src/--cert-dst 可选）
  ⑤ 启动 → AutoMigrate 补齐结构 → agent 自动重连（节点侧零操作）
  ⑥ /api/health 冒烟（ok/degraded 均 200 可读即通，异常如实报在 body）
```

**落地口径（2026-10-08 恢复批）**：`deploy/restore.sh`（set -euo pipefail，缺参/缺档/缺钥/解密失败明确报错非 0，可复跑幂等——现有库时间戳留底、同目录暂存+原子覆盖、清 WAL/SHM 残留防旧日志回放）；解密借 ferry 自身：`cmd/ferry` 加 `backup-decrypt` 子命令（-key 缺省取 FERRY_SECRET_KEY、-out 缺省去 .enc 后缀），因 `.enc` 档是主密钥派生钥 AES-256-GCM 紧凑二进制、`openssl enc` 无 GCM 能力；PG 档前置 PGDMP 魔数校验。

- 节点侧无需重装：agent 只出站重连，面板地址不变即自动回池；面板地址变更则 DNS 切换（见 §4）。

## 4. 面板迁移流程

五步操作化（每步可复制命令+验收点+回滚段）见 **deploy/MIGRATION-RUNBOOK.md**。

| 步骤 | 动作 |
| --- | --- |
| 1 | 旧面板手动备份（§2.2） |
| 2 | 新机部署 + 恢复（§3） |
| 3 | DNS 切换面板域名（TTL 提前调低） |
| 4 | agent 重连（出站自动，无需节点操作）；订阅域名不变则用户无感 |
| 5 | 旧机下线；Herald 对接在 dash 配置更新（outbox 卡）；servify 对接地址走 env（`FERRY_SUPPORT_URL`，改后重启面板） |

## 5. 健康自检（P1）

- `/api/health` 扩展：DB 可写、agenthub 在线数、备份新鲜度（距上次成功备份时长）、Herald 可达性（不单独探测——以 dash outbox 卡三态计数呈现，见下方落地口径）；
- 自检异常 → `backup_failed`/告警通道故障提示（不静默）。

**落地口径（2026-10-08 P1 备份批）**：`GET /api/health` 返回 `status`（`ok`/`degraded`）+ `checks`——`db_writable`（事务内 INSERT settings 探针强制回滚，不留行证可写）、`agents_online`（在线 agent 连接数，信息项不计 degraded）、`backup` 新鲜度（距最近落档 >48h 或从未备份 → 不新鲜）。检查异常如实上报 `degraded` 仍 200（探活方不误杀）；Herald 可达性不重复探测——通道状态以 dash outbox 卡三态计数呈现（HERALD-1 落地面）。

## 6. 数据模型与配置（已实现，2026-10-08 P1 备份批）

```sql
-- 备份记录（storage.Backup，AutoMigrate 增量）
CREATE TABLE backups (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    kind TEXT NOT NULL,             -- manual/scheduled
    path TEXT NOT NULL,
    size_bytes INTEGER NOT NULL,
    uploaded INTEGER NOT NULL DEFAULT 0,  -- 外发位成功标记（S3 外发上传成功置 1，manual 落档恒 0）
    created_at DATETIME NOT NULL
);
```

- 配置：`FERRY_BACKUP_DIR`（缺省 backups；compose 部署缺省落卷 `/data/backups`）、`FERRY_BACKUP_CRON`（缺省 daily）、`FERRY_BACKUP_KEEP`（缺省 7）、`FERRY_BACKUP_S3_ENABLED/ENDPOINT/BUCKET/ACCESS_KEY/SECRET_KEY`（外发位，默认关闭；显式开启接 S3 兼容端点外发，2026-10-09 已接入）。
