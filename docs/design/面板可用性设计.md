# 面板可用性设计

目标：面板是小内存 VPS 上的单点——备份可恢复、迁移可执行、故障语义写清楚（挂了会怎样、什么照常跑）。

## 1. 故障语义（先说清楚面板挂了会怎样）

```
面板不可达时：
  ✅ 已下发订阅照常可用（客户端持有订阅缓存与节点直连信息）
  ✅ 节点代理进程照常跑（agent 本地自治：进程拉起/退避不依赖面板）
  ✅ 隧道与用户流量不受影响
  ❌ 管理面失联：无新配置下发、无摘挂/换线决策
  ❌ 心跳上报失败（agent 本地重试缓存，恢复后补报）
  ❌ 购买/兑换/注册不可用（用户侧表现=服务正常、购买暂停）
  ◐ 告警经 Herald 的本地 outbox 攒着，恢复后补投（见《告警通道设计》§4）
```

- **结论**：面板挂 = 管理与商业化暂停，不是服务中断。这一定义决定 RTO 目标可以宽松（小时级），备份链路按此设计。

## 2. 备份

### 2.1 备什么

| 内容 | 方式 |
| --- | --- |
| 数据库（用户/节点/流量/三账） | SQLite：`.backup`（WAL 在线备份）；PG：`pg_dump` |
| 节点配置快照 | 随库（nodes.config / node_configs） |
| mTLS CA 与证书 | 文件目录一并打包 |
| 机密密文 | 随库（密文可备；**主密钥不进备份包**，另行保管） |

### 2.2 备份策略

- 周期备份（默认每日）：面板本地保留 N 份（默认 7），滚动覆盖；
- **外发位**：备份完成后可推对象存储/S3 兼容端点（插件位，P1），推失败告警（`backup_failed` 经 Herald）；
- 备份文件含机密表 → 打包加密（secret_store 派生钥），对齐《安全设计》§3；
- 手动备份：dash 一键触发（对齐 P1-6 备份导出端点）。

## 3. 一键恢复

```
新机/同机恢复流程（文档 + 脚本 deploy/restore.sh）：
  ① 部署 ferry（同版本或更高）
  ② 注入 FERRY_SECRET_KEY（主密钥）+ 解密备份包
  ③ 导入数据库（SQLite 覆盖文件 / pg_restore）
  ④ 恢复证书目录
  ⑤ 启动 → AutoMigrate 补齐结构 → agent 自动重连（节点侧零操作）
  ⑥ dash 冒烟：节点在线数/订阅可达/订单可读
```

- 节点侧无需重装：agent 只出站重连，面板地址不变即自动回池；面板地址变更则 DNS 切换（见 §4）。

## 4. 面板迁移流程

| 步骤 | 动作 |
| --- | --- |
| 1 | 旧面板手动备份（§2.2） |
| 2 | 新机部署 + 恢复（§3） |
| 3 | DNS 切换面板域名（TTL 提前调低） |
| 4 | agent 重连（出站自动，无需节点操作）；订阅域名不变则用户无感 |
| 5 | 旧机下线；Herald/servify 对接地址若变更，dash 配置更新 |

## 5. 健康自检（P1）

- `/api/health` 扩展：DB 可写、agenthub 在线数、备份新鲜度（距上次成功备份时长）、Herald 可达性；
- 自检异常 → `backup_failed`/告警通道故障提示（不静默）。

## 6. 数据模型与配置

```sql
-- 备份记录（P1）
CREATE TABLE backups (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    kind TEXT NOT NULL,             -- manual/scheduled
    path TEXT NOT NULL,
    size_bytes INTEGER NOT NULL,
    uploaded INTEGER NOT NULL DEFAULT 0,  -- 外发是否成功
    created_at DATETIME NOT NULL
);
```

- 配置：`FERRY_BACKUP_DIR`、`FERRY_BACKUP_CRON`、`FERRY_BACKUP_KEEP`、`FERRY_BACKUP_S3_*`（外发位）。

## 7. 分期

| 阶段 | 内容 |
| --- | --- |
| P0 | 手动备份/导出端点（对齐 P1-6 提前）；恢复流程文档化 |
| P1 | 周期备份+滚动保留+外发插件位；备份记录与失败告警；health 自检扩展；迁移 runbook 落 deploy/ |

> 合规定位：ferry 是代理集群管理工具，部署与运营的合规责任在部署者（见《合规定位声明》）。
