# 流量节省设计

目标：把「哪里可以省流量」的出口逐个堵住——分流直连、缓存、拦截、压缩复用、配额联动，并把省下的量报表化（真数字，与成本看板联动）。

## 0. 省流量出口总览

| # | 出口 | 阶段 | 省的是 |
| --- | --- | --- | --- |
| ① | GeoIP 分流（国内直连） | P0 | 国内流量不进隧道 |
| ② | 静态域名分流 + 缓存层 | P0/P1 | 重复静态资源 |
| ③ | 广告/追踪器拦截 | P1 | 广告与追踪流量 |
| ④ | 压缩 + 连接复用/TLS 会话恢复 | 报表化 P1 | 传输开销（多为既有能力，报表呈现） |
| ⑤ | 配额联动（超阈值降速/切低成本节点） | P1 | 超额高价流量 |
| ⑥ | 节省报表（dash） | P1 | ——（度量以上全部） |

MITM 缓存默认不做（解密改造收益低、风险高，仅自用注释位保留）。

## 1. GeoIP 分流（P0）

- 规则：国内 IP/域名（geoip:cn + geosite:cn 类规则）**直连不进隧道**，其余走代理——出海场景下的最大头。
- 实现：走被管代理进程（xray/sing-box）的 routing 规则，节点配置模板带规则段；面板下发的配置模板内置。
- **规则库可更新**：geoip/geosite 数据文件随配置分发（config.push 落盘 + reload），dash 可触发更新；库版本入节点配置快照。

```
客户端请求 → 入口代理进程 routing
   ├─ geoip:cn / geosite:cn ──→ direct（不走隧道，不耗落地流量）
   └─ 其他 ────────────────→ relay 隧道 → 落地
```

## 2. 静态域名分流 + 缓存层（P0/P1）

- **静态域名清单直连/CDN**（P0）：常见静态资源域名清单（与 geosite 复用同机制）分流直连——静态资源大多国内有 CDN，绕隧道反而慢且费流量。
- **缓存层插件位**（P1）：入口节点可选装 nginx cache / Squid（独立进程，agent 视其为被管进程的一种 kind），对命中清单的静态域名做边缘缓存；命中统计随心跳上报。
- 自建静态资源缓存命中率高（大量重复请求），未命中才回源。

**落地口径（2026-10-08 SAVE-3）**：缓存层不做专用通道，走既有被管进程面——agent 配置的 ProcSpec 加 `metrics_url`（HTTP GET 指标接口，JSON 数字对象或文本 key-value 行，空=不采集），nginx cache / Squid 按普通被管进程配置（kind 仅作标签，规格自由），Manager 15s 轮询挂进状态快照随心跳上报；服务端心跳处理器把 ProcStatus 逐节点逐进程 upsert 进 `node_proc_statuses`（指标 JSON 落 metrics 列），dash 节点页「进程」对话框回读（GET /api/nodes/:id/procs）。缓存本体（命中清单、缓存目录、回源）由部署侧在 nginx/Squid 配置里自理，ferry 只管进程与统计面。

## 3. 广告/追踪器拦截（P1）

- 节点侧 DNS 屏蔽广告与追踪域名：被管代理进程的 DNS 段配屏蔽名单（名单可配，默认用成熟开源名单，如 anti-AD 类）；
- 省流量 + 提速（少建连）；名单版本与更新同规则库机制；
- **拦截计数上报**：拦截条数随心跳/流量上报，进节省报表。

**落地口径（2026-10-08 SAVE-4）**：屏蔽走 routing 规则段而非 DNS——ad-block 清单（`geosite:category-ads-all`，官方 geosite.dat 自带）命中即发 `block` 出站（blackhole），`routing.Merge` 保证 block 出站存在（模板自带则原样保留不重复）；dash 开关 `PUT /api/routing/ads {enabled}`（settings 键 `routing_ads_enabled`，缺省开，关后渲染不再含屏蔽段——已下发配置不动，重渲染重发才生效）；名单更新与 geoip/geosite 同机制走 rulelib 分发（anti-AD 等开源名单推同格式 geosite 文件覆盖）。**拦截计数按字节不按条数**：xray stats 无请求条数计数，agent 同周期另查 `outbound>>>` 计数取 block 出站上下行增量随流量上报（`ProcTraffic.BlockedBytes` → `node_traffic_logs.blocked_bytes`）——被拦字节本身就是省下的流量，比 §6 的「条数×估算均耗」更准且免估算常量。

## 4. 压缩与连接复用/TLS 会话恢复（报表化 P1）

- 能力多为传输层既有：HTTP/2、HTTP/3 的 header/文本压缩、连接复用、TLS 会话恢复——**本节做的是报表化**：
- 心跳/流量上报带复用指标（连接复用率、会话恢复率），报表呈现传输开销的节省，不做新机制。

**不可执行，不落（2026-10-08 核实）**：这些计数在被管内核侧不存在——xray/sing-box 的 stats API 只导出流量计数（inbound/outbound/user 上下行字节），没有连接复用率、TLS 会话恢复率或压缩量计数；TLS 会话恢复发生在用户客户端侧，被管进程无从观测。报表不自造数；能力本体随内核/客户端版本自然受益，待内核将来导出计数再接 SAVE-4 的同一上报面（outbound 计数查询已在案）。

## 5. 配额联动（P1，已落地 2026-10-08 SAVE-6）

- 用户流量/费用超阈值 → 自动动作（可配，默认关）：
  1. ~~**降速**：对该用户后续连接限速（节点配置模板按用户段落）~~ **不可执行，不落**——节点配置模板是共享凭据（单 uuid/password），代理进程侧无按用户身份，带宽整形无从挂靠；与 P2-3「按用户带宽限速不做」同口径；
  2. **切低成本节点**（落地形态=**订阅降档**）：生效中的联动行让该用户订阅只出低成本档入口（包月零边际成本或单价不超档线的按流量节点），客户端刷新订阅后新连接自然落到低成本落地，存量连接不动——即「把该用户新连接分到成本档更低的落地」在本架构下的可执行实现。
- 触发两档（dash 可配，启用时至少一档）：**流量档**=窗口用量达个人配额 N%（缺省 90%，仅配额>0 用户）；**费用档**=窗口折算费用达绝对阈值（分；配额 0 的不限量用户唯一触发档，折算=逐条记账乘所在按流量节点单价，口径对齐 alloc 成本判定）。
- 留痕 `quota_actions`：触发/释放全留（触发器、用量/配额/费用/档线快照、reason 对齐 landing_assignments.reason 习惯，released_at 空=生效中）；降档订阅按**行上快照档线**过滤，配置后续调整不影响已生效行；联动被关全量释放。
- 触发即发 system 站内信告知降档与恢复口径（NT 体系，与发放到账同通道）；释放不另发信（订阅恢复是好消息，用户刷新即见）。
- 扫表 `quota.LinkLoop`（FERRY_QUOTA_LINK_SEC 默认 600s，启动即跑一轮）；订阅出口直接读留痕即时生效，周期只影响留痕与通知的及时性。dash 配置与留痕在成本看板同页（GET/PUT /api/quota-link）。

## 6. 节省报表（dash，P1）

```
节省量（每日/月，按节点与全网汇总）
├─ 直连分流：命中国内直连规则的流量 GB（不进隧道）
├─ 缓存命中：命中缓存返回的流量 GB ×（1-回源比）
├─ 广告拦截：拦截请求数 × 估算均耗（可配常量）——落地改用真实被拦字节（SAVE-4，node_traffic_logs.blocked_bytes），免估算
└─ 合计：省下 GB × 节点流量单价 = 折算费用（与成本看板同口径同页）
```

- 数据源：心跳与流量上报里的分流/命中/拦截计数 + `save_stats` 落表；
- **给用户看的真数字**：panel 用户侧展示其用量中「已为你省下」的汇总（月账单邮件附亮点，联动《用户触达设计》）。

**落地口径（2026-10-08 SAVE-7）**：`save_stats` 按 (node_id, UTC 日) 唯一，聚合器 `save.Loop`（`FERRY_SAVE_STATS_SEC` 缺省 600s，启动即跑一轮）按 node_traffic_logs 自增 id 水位增量累计（水位存 settings；无水位先清空重建防重复）；数据源为 agent 出站计数——直连字节（direct 出站）与拦截字节（block 出站）**在同一次 QueryStats 里取**（reset 按前缀清零，分开查互踩清零），随流量上报落 `node_traffic_logs.direct_bytes/blocked_bytes`；`cache_hit_bytes` 列预留（缓存层字节指标接 SAVE-3 metrics 后汇入）。报表 `GET /api/save-stats?days=N`（按日行+全网合计），折算费用按节点流量单价**现算不入库**（单价调整不回改历史），仅按流量计费节点计价，与成本看板同口径同页（dash 成本页「流量节省」区）。

**落地口径（2026-10-08 SAVE-8）**：panel 用户侧「已为你省下」走 `GET /api/panel/savings`（订阅令牌身份），窗口=自然月至今（UTC）对齐月账单亮点口径；节点级节省计数出自 agent 出站计数**无用户身份**，按「用户在该节点当月记账流量占比 × 该节点当月节省字节」折算（可复核的估算式；节点当月无用户记账不摊派），缓存命中列随 SAVE-3 metrics 汇入后自动进返回。月账单邮件附亮点待触达批的月账单例行邮件落地时接本接口作数据源（与 HERALD-4 的 bill 随触达批同口径）。

```sql
-- 节省统计（按节点按日汇总，P1）
CREATE TABLE save_stats (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    node_id INTEGER NOT NULL,
    day DATE NOT NULL,
    direct_bytes INTEGER NOT NULL DEFAULT 0,    -- 直连分流
    cache_hit_bytes INTEGER NOT NULL DEFAULT 0, -- 缓存命中
    blocked_count INTEGER NOT NULL DEFAULT 0,   -- 拦截条数
    created_at DATETIME NOT NULL,
    UNIQUE(node_id, day)
);
```
