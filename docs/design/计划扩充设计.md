# 计划扩充设计

三块规划能力：**供给**（一键开服与自动入池）、**自愈**（被封自动恢复）、**商业化扩展**（分销/代理体系）。供给与自愈同「入口与负载均衡」的探测/摘挂闭环相接，分销与支付三账相接。

> 落地状态（审计注 2026-10-08）：§1 供给与 §2 自愈**已实现**（`server/internal/provision`——tofu HCL 渲染与受控执行、cloud-init 启动编排、池自动补位 replenish；`server/internal/recovery`——dns_switch 域名切换（L1）、standby_promote 备机提升（L2）、L3 联动供给流水线，`recovery_actions` 全程留痕，dash 可回放）；§3 分销 P2 维持不开工（拍板）。以下原文保留设计口径，落地细节以源码为准。

## 1. 一键开服与自动入池（P1 后段）

### 1.1 目标

新节点从「点创建」到「入池可用」5 分钟：dash 选模板 → 供给引擎开机 → cloud-init 装 agent → 自动注册 → 配置下发 → 探测通过 → 入池。

### 1.2 选型对比：云 SDK 薄封装 vs OpenTofu

| 维度 | 云 SDK 薄封装 | OpenTofu/Terraform |
| --- | --- | --- |
| 云覆盖 | 每家 SDK 各写一遍，维护随 provider 数线性涨 | 官方 provider 直用（阿里云/腾讯云/AWS/Vultr/Hetzner…） |
| 资源建模 | 自定模型，漂移与幂等自己处理 | state、plan/apply、幂等与漂移检测现成 |
| 依赖体积 | 小（按需引 SDK） | 需随部署带 tofu 二进制（或宿主安装） |
| 运维心智 | 自造轮子长期维护 | 社区通用，HCL 配置可视可 diff |

**结论：底座 = OpenTofu（开源 Terraform 分叉，license 友好）作供给引擎 + cloud-init 做开机初始化**；ferry 不自研供给引擎、不逐家封 SDK。

### 1.3 ferry 只做三层

1. **节点模板**：机型/区域/带宽/计费口径/方向与线路标签/预装角色——`provision_templates` 表，dash 录入；
2. **供给执行**：模板渲染 HCL（或直接调 `tofu` CLI）→ `plan/apply` 受控执行，生成/更新资源；state 集中存面板侧（落地口径：tofu 工作目录 `FERRY_TOFU_DIR` 存 state 文件，执行留痕落 `provision_jobs` 行——无独立 `provision_state` 表），单实例不并发 apply；
3. **入池流水线**：预创建节点行（`status=provisioning`，预签发节点 token）→ cloud-init 注入 token 装 agent → agent 首连注册 → 元数据补全（模板带的方向/线路/区域/成本默认值）→ 模板配置下发 → 探测通过 → `online` 入池。

### 1.4 初始化（cloud-init）

- 装 agent 二进制 + systemd 常驻 + 写配置（面板地址、预签发 token、角色与元数据初值）；
- 首连即注册入池，面板把 `provisioning → online` 的流水线状态写入节点行，失败留原因。

### 1.5 state 与凭据安全

- 云 API 密钥 dash 录入后**加密存储**，对齐 R24 加密面口径：主密钥不入库（部署环境变量/文件提供），密文 AES-256-GCM 落库，前端不回显明文；
- 凭据仅在 server 执行供给时解密使用，日志与 state 不落明文密钥；
- tofu state 含资源敏感信息，同样加密存面板侧。

### 1.6 阶段

P1 后段先通 1 家 provider（海外易接的一家），验证 5 分钟链路；多 provider 靠 OpenTofu provider 生态横向扩，不改 ferry 三层结构。

## 2. 被封自动恢复（P1，与区域探测/摘挂同批）

### 2.1 闭环位置

```
边缘探测发现被封（peer 探测 blocked / 区域故障判封）
  → 判封状态机（面板聚合，复用 E-14/E-15）
  → 摘挂先行保可用（订阅换线）
  → 恢复流水线自动补位
  → 探测确认恢复 → 复位 → 订阅热更新回切
```

### 2.2 恢复三件套（可组合，按代价分级）

| 级别 | 手段 | 耗时 | 说明 |
| --- | --- | --- | --- |
| L1 | 域名前置 + 自动 DNS 切换 | 秒级 | 入口 SNI 用域名；DNS 记录切备用 IP/CDN——域名商 API 做成插件位（DNS-01 也复用） |
| L2 | IP 池储备与自动补位 | 分钟级 | 预备 IP/备用机清单轮换补位；池空自动联动 §1 开新机 |
| L3 | 一键开新机 | ~5 分钟 | 走 §1 供给流水线 |

- 证书 ACME 自动签发续期：新 IP/域名到位后自动签发（HTTP-01/DNS-01）、到期自动续——面板管编排与到期告警，签发执行复用 acme.sh/certbot 类外部工具位。
- 域名前置：SNI/Host 用常态域名、后端指向真实入口，配合 DNS 切换做到「域名不换、IP 随换」。

### 2.3 升级策略

- 流水线按 L1 → L2 → L3 顺序推进，每级超时未恢复进下一级；
- 全部失败/超时 → 告警升级人工（经 Herald 投递，见《安全与运维设计》告警通道篇）；
- 恢复过程全程留痕（`recovery_actions` 记录级别/动作/结果），dash 可回放。

## 3. 分销/代理体系（P2）

> 2026-10-08 续跑令点名解禁开工（原拍板「远期不开工」对本组失效）；本节扩为落地级设计稿，按 §3.4 分期连做。

### 3.1 模型（定稿）

- **代理身份独立于 users**：代理不是终端用户（无配额/订阅语义），独立 `distributors` 表自带登录凭证——不污染 users 单一语义，代理停用不动用户面。
- **层级口径**：单级代理（不做多级分销树）。代理从面板拿折扣额度，卖二级卡密；二级卡 = 代理名下批次，代理间互不可见，面板全局可见。
- **佣金口径（余额域定稿）**：卡面价由批次定价（代理批次可自定 `price_cents`）；终端兑换实付=卡面价（三账口径不变）；`discount_percent` 为佣金比例——面板让利部分归代理。
- **账目打通**：兑换订单从卡批次归属带入 `distributor_id`（三账一条 provider=card 订单）；`distributor_ledger` 按 `order_no` 与三账串联，dash 对账视图加代理维度。

```sql
CREATE TABLE distributors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,                -- 代理登录名（独立登录，非 users）
    password_hash TEXT NOT NULL,                  -- bcrypt 同管理员口径
    discount_percent INTEGER NOT NULL DEFAULT 0,  -- 佣金比例%（面价让利部分，0-100）
    note TEXT,
    enabled INTEGER NOT NULL DEFAULT 1,           -- 停用即禁登录，账目保留
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

-- card_batches / orders 增列（ensureColumns 增量迁移）
distributor_id INTEGER NOT NULL DEFAULT 0,        -- 0=面板自营；>0=代理批次/代理订单（兑换时从卡批次带来）

CREATE TABLE distributor_ledger (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    distributor_id INTEGER NOT NULL,
    order_no TEXT NOT NULL DEFAULT '',            -- 与三账订单串联（sale/commission 带）
    kind TEXT NOT NULL,                            -- sale/commission/payout/adjust
    amount_cents INTEGER NOT NULL,                 -- 正=代理得，负=扣减
    note TEXT,
    created_at DATETIME NOT NULL
);
CREATE INDEX idx_distributor_ledger ON distributor_ledger(distributor_id, id);
```

- **ledger 四类与余额域**：`sale`（+面价，售卡收入留痕，**不进余额**只做统计）；`commission`（+面价×佣金比例，进余额——面板欠代理）；`payout`（−金额，管理员结算打款扣余额）；`adjust`（±，人工调整）。**未结算余额 = Σcommission + Σadjust − Σpayout**。
- **结算**：dash 管理面手动打款（落 `payout` 行+备注），不做自动打款；账期=线下约定，面板只记账。
- **发卡权限**：代理批次由管理员建（归属落 `distributor_id`），DS-3 起代理可自查自有批次/卡密；代理不可改佣金比例与批次归属。

### 3.2 代理面板视图（DS-3）

- 代理角色登录（非管理员、非用户）：`POST /distributor/login` 独立端点（JWT `role=distributor`，bcrypt 复用管理员哈希口径，防爆破复用限速）；
- 只看自己的：客户（自有批次的兑换订单）/卡密批次与卡密/用量/结算（余额+流水，只读——结算动作在管理员面）；
- 与 dash 共用前端框架按角色裁剪可见面（`ferry.dist.token` 独立存储键，守卫区分角色）——与 P2-2「不做多级管理员」不冲突：代理是销售渠道角色，不是运维管理员。

### 3.3 与优惠联动

代理折扣与优惠码**不叠加，取对用户更优者**——叠加规则一旦开放，三账的实付口径会失真，先以「取优」保账目清晰。

### 3.4 分期

| 阶段 | 内容 |
| --- | --- |
| DS-1 账目层 | 三表落库（distributors/card_batches.distributor_id/orders.distributor_id/distributor_ledger）；代理 CRUD；兑换链路带归属与分润落账（commission 按 order_no 串联） |
| DS-2 管理面 | dash 代理管理卡（建号/停用/佣金比例）、结算打款（payout）、对账视图加代理维度（售卡收入/佣金/已结算/未结算汇总） |
| DS-3 代理自面 | 独立登录 + 代理视图裁剪（批次/卡密/客户/用量/结算只读）；与优惠码不叠加取优在兑换链路落地 |

## 4. 数据模型汇总

> 审计注（2026-10-08）：下列 DDL 为**设计期稿**，实现已演进（以 `server/internal/storage/models.go` 为准）：`provision_templates` 实际以 `provider_id` 关联 providers 表并平铺 plan/region/image/成本单价/role/transport/config 列；`provision_jobs` 无 node_id/tofu_state 列（state 存 `FERRY_TOFU_DIR` 文件），status 枚举为 running/ok/failed，另带 action/plan 或 apply 与 log；`recovery_actions` 实际为 level 整数（1/2/3）、state（running/ok/failed/skipped/timeout）并关联 recovery_id。`distributors`/`distributor_ledger` 属 §3 分销（原按拍板不开工，2026-10-08 续跑令解禁，DDL 已更新为 §3.1 定稿版随 DS 批落地）。

```sql
-- 供给模板（设计期稿，实现差异见上注）
CREATE TABLE provision_templates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    provider TEXT NOT NULL,            -- 阿里云/腾讯云/aws/vultr/hetzner
    spec TEXT NOT NULL,                -- 机型/区域/镜像（HCL 变量 JSON）
    role TEXT NOT NULL DEFAULT 'landing',
    direction TEXT NOT NULL DEFAULT 'out',
    line_type TEXT NOT NULL DEFAULT '普通',
    billing_type TEXT NOT NULL,        -- 按流量/包月/固定带宽
    bw_up_mbps INTEGER NOT NULL DEFAULT 0,
    bw_down_mbps INTEGER NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL
);

-- 供给执行与 state（设计期稿：实现无 tofu_state 列，state 存 FERRY_TOFU_DIR 文件）
CREATE TABLE provision_jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    template_id INTEGER NOT NULL,
    node_id INTEGER,                   -- 预创建的节点
    status TEXT NOT NULL,              -- pending/running/succeeded/failed
    tofu_state BLOB,                   -- 加密后的 state 快照
    error TEXT,
    started_at DATETIME NOT NULL,
    finished_at DATETIME
);

-- 恢复流水线留痕（设计期稿，实现差异见上注）
CREATE TABLE recovery_actions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    node_id INTEGER NOT NULL,
    level TEXT NOT NULL,               -- dns/ip_pool/new_machine
    action TEXT NOT NULL,
    result TEXT NOT NULL,              -- succeeded/failed/timeout
    detail TEXT,
    triggered_by TEXT NOT NULL,        -- probe/fault_dim/manual
    created_at DATETIME NOT NULL
);

-- 代理与分润（定稿版 2026-10-08，随 DS 批落地；口径见 §3.1）
CREATE TABLE distributors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,                -- 代理登录名（独立登录）
    password_hash TEXT NOT NULL,                  -- bcrypt
    discount_percent INTEGER NOT NULL DEFAULT 0,  -- 佣金比例%（面价让利归代理）
    note TEXT,
    enabled INTEGER NOT NULL DEFAULT 1,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);

CREATE TABLE distributor_ledger (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    distributor_id INTEGER NOT NULL,
    order_no TEXT NOT NULL DEFAULT '',            -- 与三账订单串联
    kind TEXT NOT NULL,                            -- sale/commission/payout/adjust
    amount_cents INTEGER NOT NULL,                 -- 正=代理得，负=扣减
    note TEXT,
    created_at DATETIME NOT NULL
);
```
