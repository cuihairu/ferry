# 支付设计

目标：零资质先闭环（卡密兑换），USDT 自动收款排二段，微信/支付宝商户直连留接口位等资质。全程三账对应：订单、支付流水、发放记录可互相追溯。

## 1. Provider 抽象

契约放 `packages/payment`（Go module，server 与 payments/ 插件共用），插件实现放 `payments/`。

```go
// packages/payment/provider.go
type Provider interface {
    Name() string
    // CreateOrder 创建收款订单，返回外部收款标识与跳转地址（卡密类为空）。
    CreateOrder(ctx context.Context, o Order) (Receipt, error)
    // Verify 验证异步回调，返回可信的订单号与外部交易号。
    Verify(ctx context.Context, raw []byte) (Callback, error)
}

type Order struct {
    OrderNo   string    // 面板生成的订单号
    UserID    int64     // 目标用户
    AmountCents int64   // 金额（分），卡密兑换为 0
    Product   string    // 商品描述，如「50GB 流量卡密」
    CreatedAt time.Time
}

type Receipt struct {
    Provider  string // card / epusdt / wechat / alipay
    PayURL    string // 收款页地址，卡密为空
    ExternalID string // 外部订单号（epusdt 等），卡密为空
    ExpiresAt time.Time
}

type Callback struct {
    OrderNo    string
    ExternalID string // 交易号/txid
    AmountCents int64
    PaidAt     time.Time
    Raw        []byte  // 原始回调，落流水表备查
}
```

插件注册：各渠道包内 `init()` 自注册（`payments/epusdt`、`payments/wechat`、`payments/alipay`），server 主入口空导入装配（`server/cmd/ferry/main.go`）；未接通的 Provider 保留 stub 返回「未启用」。

## 2. 数据模型（三账）

```sql
-- 账一：订单（谁该收多少）
CREATE TABLE payment_orders (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    order_no      TEXT    NOT NULL UNIQUE,
    user_id       INTEGER NOT NULL INTEGER NOT NULL -- 无 DB 外键：财务记录不随用户删除，应用层按 id/order_no 串联,
    provider      TEXT    NOT NULL,              -- card / epusdt / ...
    amount_cents  INTEGER NOT NULL DEFAULT 0,
    product       TEXT    NOT NULL,
    status        TEXT    NOT NULL DEFAULT 'pending', -- pending/paid/failed/expired/refunded（refund 仅 paid→refunded，对账见 §2 对账口径）
    created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    paid_at       DATETIME
);

-- 账二：支付流水（外部实际发生的收付）
CREATE TABLE payment_transactions (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    order_no     TEXT    NOT NULL TEXT NOT NULL -- 无 DB 外键，应用层按 order_no 串联,
    provider     TEXT    NOT NULL,
    external_id  TEXT    NOT NULL,               -- 交易号/txid/卡密批次外键标识
    amount_cents INTEGER NOT NULL,
    direction    TEXT    NOT NULL DEFAULT 'in',  -- in/out
    raw          TEXT,                           -- 原始回调或请求体
    occurred_at  DATETIME NOT NULL,
    created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(provider, external_id)
);

-- 账三：发放记录（用户实际拿到的权益）
CREATE TABLE grants (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    order_no    TEXT    NOT NULL TEXT NOT NULL -- 无 DB 外键，应用层按 order_no 串联,
    user_id     INTEGER NOT NULL INTEGER NOT NULL -- 无 DB 外键：财务记录不随用户删除，应用层按 id/order_no 串联,
    grant_type  TEXT    NOT NULL,                -- add_quota / extend_days
    grant_value INTEGER NOT NULL,                -- 字节数或天数
    snapshot    TEXT    NOT NULL,                -- 变更前后快照 JSON
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

对账口径：`paid 订单 ⇔ ≥1 条流水 ⇔ ≥1 条发放`，三者按 `order_no` 串联；dash 对账视图按订单分组给出缺失环节。

## 3. 卡密系统（一段，零资质）

### 3.1 表

```sql
CREATE TABLE card_batches (
    -- price_cents INTEGER NOT NULL DEFAULT 0,  -- 在线售价（0=仅兑换不出售），源码 models.go:99 已有
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL,
    grant_type  TEXT    NOT NULL,       -- add_quota / extend_days
    grant_value INTEGER NOT NULL,       -- 字节数或天数
    total       INTEGER NOT NULL,
    expired_at  DATETIME,               -- 卡密本身的有效期，空为永久
    created_by  TEXT    NOT NULL,
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE card_codes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    batch_id   INTEGER NOT NULL, -- 批次删除 DB 级联连带卡密（CardBatch.Codes OnDelete:CASCADE，SQLite foreign_keys=1；handler/card.go 删批次援引本节口径），非应用层关联
    code       TEXT    NOT NULL UNIQUE, -- 明文存储，管理员需导出发放
    status     TEXT    NOT NULL DEFAULT 'unused', -- unused/used/disabled
    fail_count INTEGER NOT NULL DEFAULT 0,
    used_by    INTEGER INTEGER, -- 无 DB 外键
    used_at    DATETIME,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

删除批次时 DB 级联连带删除名下卡密（`CardBatch.Codes` 的 `OnDelete:CASCADE` 约束 + 连接级 `foreign_keys=1`）——导出发放前误建批次可整体回收；与仓库「财务三账不设 DB 外键」口径无关（卡密表不在三账内）。

### 3.2 生成与兑换

- 生成：`crypto/rand` 取随机数，字符集去易混淆字符（`23456789ABCDEFGHJKMNPQRSTUVWXYZ`），分组展示（如 `XXXX-XXXX-XXXX`）；dash 按批次生成并支持导出 CSV。
- 兑换：`UPDATE card_codes SET status='used', used_by=?, used_at=? WHERE code=? AND status='unused'` 原子核销，行数为 0 即已用/禁用；核销成功后写订单（provider=card, amount=0, status=paid）→ 写流水（external_id=卡密 id）→ 写发放（对应 grant_type/grant_value）→ 执行权益：`quota_bytes += v` 或 `expires_at += v 天`（到期为空视为创建默认时长 +v 天）。
- 幂等：唯一约束与原子 UPDATE 保证同一码只发放一次。

### 3.3 防爆破

- 兑换接口按 IP 限速（内存滑动窗口，失败 N 次后一段时间拒绝）；
- 按码计数：`fail_count ≥ 5` 自动置 disabled（仅已存在码行计数，未知码无行不计数，仅 IP 限速生效）；
- 兑换错误响应不区分「码不存在/已用/禁用」，统一「兑换失败」；
- 大批量生成仅管理员（dash）可用，与兑换接口分离。

## 4. USDT 自动收款（二段）

对接开源 epusdt 系网关（TRC20 收款）：

1. panel 下单 → server 调 `Provider.CreateOrder` → 得 `PayURL` 收银台；
2. 用户支付，epusdt 异步回调 server → `Provider.Verify` 验签（回调密钥）→ 金额与订单一致；
3. 落流水（external_id=txid，唯一约束防重放）→ 订单置 paid → 执行发放（与卡密共用 grants 流程，或按商品配置自动发码/直接开通）；
4. 回调处理事务化：流水、订单、发放同一事务，重复回调按 `UNIQUE(provider, external_id)` 幂等忽略。

配置：`FERRY_EPUSDT_URL`、`FERRY_EPUSDT_TOKEN`（网关 API token）、`FERRY_EPUSDT_NOTIFY_URL`（回调地址，需对外可达）——由 payments 插件直读 env，不进 `server/internal/config/config.go`。

## 5. 微信/支付宝商户直连（三段，等资质）

- `payments/wechat`、`payments/alipay` 留 Provider stub（接口方法齐全，返回「未启用」）；
- 后续实现 Native/JSAPI 下单、平台证书验签、对账文件下载，插件接入不动 server 主干。

## 6. 时序（兑换）

```
panel 用户输入卡密
  → POST /api/panel/redeem {code}（用户正道，订阅令牌身份）；`POST /api/redeem {code,user_id}` 为管理/测试口（需显式 user_id）
  → 限速检查 → 原子核销 card_codes
  → 事务: payment_orders(card, paid) + payment_transactions + grants
  → 执行权益(users) → 返回结果
```
