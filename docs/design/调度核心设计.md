# 调度核心设计（总纲）

定位：ferry 调度的**总纲**——所有采集、画像、决策、执行类设计篇挂到本纲。核心问题只有一个：**拿什么信号、给哪个权重、做什么决策**。

## 0. 五段闭环

```
①采集 ──→ ②画像 ──→ ③决策 ──→ ④执行 ──→ ⑤反馈 ──┐
  │          │        │        │        │          │
  │ agent 心跳  │ 节点画像  │ 分配/摘挂 │ config. │ 决策质量评估 │
  │ probe.report│ 静态+动态 │ /换线/传输│ push/订阅│ 权重再校准  │
  │ 流量上报    │ +历史    │         │ /摘挂动作 │          │
  └────────── 周期循环（窗口聚合，事件驱动加速）────────────┘
```

- **采集原则：只采影响决策的信号**——每个采集字段都能在下表指出它改哪个权重，指不出就不采（省小内存节点的开销）。

## 1. 采集维度 → 决策权重映射表（总表）

| # | 采集字段 | 来源 | 改哪个权重 | 决策消费方 |
| --- | --- | --- | --- | --- |
| 1 | `verdict`（healthy/sick） | probe.report | **健康权重**（乘性大因子） | 摘挂/分配 |
| 2 | `rtt_ms` / `loss_pct` | probe.report | 健康权重内的质量分 | 分配/订阅测速展示 |
| 3 | `blocked`（被封判定） | peer 探测 | 直接触发摘挂（不走权重） | 摘挂/恢复流水线 |
| 4 | 区域故障状态 | 面板聚合（dimension_status） | **区域组开关**——整组切走，不做权重微调 | 区域摘挂 |
| 5 | ISP 故障状态 | 面板聚合 | **运营商组开关**——同 ISP 一起切 | 运营商摘挂 |
| 6 | 连接数 | 心跳 | **负载权重**（最小连接） | 落地分配 |
| 7 | 带宽利用率（吞吐/校准容量） | 心跳 | 负载权重（>80% 折半进新连接） | 落地分配/预警 |
| 8 | CPU / 内存 | 心跳 | 负载权重（轻因子） | 落地分配 |
| 9 | 流量单价（按流量计费节点） | nodes 元数据 | **成本档权重**（三档可配） | 落地分配 |
| 10 | 校准带宽 bw_up/down | 测速校准 | **容量权重**（分母）——3M 少分 | 落地分配 |
| 11 | `direction` | 元数据 | 非权重——**池选择前置**（出海/回国分流） | 池路由 |
| 12 | `line_type`（线路类型） | 元数据 | **线路档权重**（回国线：cn2_gia/iplc 优先） | 回国分配 |
| 13 | 时段历史质量（晚高峰曲线） | probe_reports 聚合 | **历史权重**（P2：高峰预调度/入口轮换） | 分配/轮换 |
| 14 | 用户回传（客户端测速/可用性） | 订阅端点回传（P2） | 健康权重的**外部修正项**（边缘视角） | 分配/摘挂 |

- 权重合成分（P1 自动均衡）：`score = 健康 × (负载权重) × 容量 × 成本档 × 线路档`——各项权重系数 dash 可配，默认给均衡档；区域/运营商故障是**开关**（切组），不进乘法。

## 2. 节点画像模型

```
节点画像 = 静态层 + 动态层 + 历史层
├─ 静态层：注册/面板元数据（区域/ISP/方向/线路/套餐/成本/角色/传输）
│          —— 变更频率低，面板可改以面板为准
├─ 动态层：心跳负载（连接/带宽/CPU）+ 探测窗口聚合（verdict/rtt/loss）
│          —— 窗口滚动（默认 60s），事件加速（alarm 即时入窗）
└─ 历史层：probe_reports 按时段聚合的质量曲线 + landing_assignments 分配史
           —— 晚高峰报表/月度预估/轮换决策的数据源
```

- 画像不另建大表：静态=nodes 列，动态=内存窗口+dimension_status，历史=probe_reports/landing_assignments 聚合查询。

## 3. 决策四类

| 决策 | 输入 | 输出 | 执行链路 | 设计出处 |
| --- | --- | --- | --- | --- |
| 落地分配 | 画像动态层+成本/容量/线路档 | landing_assignments（权重表） | config.push 下发入口的落地列表 | 入口设计 §C.5 |
| 摘挂 | 探测窗口聚合（单点/区域/ISP） | 摘除/复位动作 | 摘挂→换线→补位 | 入口设计 §C.4.3 |
| 换线/恢复 | 判封状态机 | L1 DNS→L2 IP→L3 开新机 | 恢复流水线+recovery_actions | 计划扩充 §2 |
| 传输选择 | 区域×传输探测结论 | transport 标注与配置 | config.push（换配置不改架构） | 入口设计 §C.4.4 |

- 决策原则：**区域/ISP 级处置优先于单点处置**（区域断网时逐个摘=葫芦娃救爷爷还误杀好节点）；决策留痕（reason 写入 assignments/recovery_actions），可回放。

## 4. 执行与反馈

- **执行**：一切执行动作收敛到三条链路——`config.push`（配置/换线/传输）、订阅下发（入口列表/测速）、面板动作（摘挂/分配落库）；执行结果（config.ack）失败即回滚告警。
- **反馈闭环**：分配生效后的窗口探测与负载变化回写画像 → 决策质量评估（分给 A 的连接质量 vs 预期）→ 偏差大提示权重再校准（人工调参为主，P2 才考虑自动调）。

## 6. 分期

| 阶段 | 内容 |
| --- | --- |
| P0 | 映射表 1-12 落地：探测与心跳采集进画像，手动分配+区域/ISP 聚合判定（开关型） |
| P1 | 权重合成与自动均衡（负载/容量/成本/线路四权重）、摘挂闭环、决策留痕回放 |
| P2 | 历史权重（晚高峰预调度/入口轮换）、用户回传修正、权重自动再校准 |
