# agent 架构设计（核心 + 角色组件）

目标：单个小内存 VPS 上承载全套 agent 能力而不撑爆内存——核心恒定最小集（目标 ≤10MB），角色组件按节点角色装配、独立进程、可插拔。对应 todo A-13/A-14 与 E-4..E-7。

## 1. 分层总图

```
                 面板（管理面）
                      │  仅出站 WebSocket（agentproto）
                      ▼
┌─ 节点主机 ─────────────────────────────────────────────┐
│                                                        │
│  ┌─────────────────────────────┐                       │
│  │ agent 核心（ferry-agent）     │  ← 常驻，目标 ≤10MB    │
│  │  ├─ 注册/心跳（元数据/负载）    │                       │
│  │  ├─ 代理进程管理              │                       │
│  │  ├─ 配置接收/校验/回滚         │                       │
│  │  └─ 流量/负载上报             │                       │
│  └──────────┬──────────────────┘                       │
│             │ 本机 IPC（unix socket）+ 配置文件           │
│      ┌──────┴───────────────┬──────────────┐           │
│      ▼                      ▼              ▼           │
│  ┌────────────┐    ┌────────────┐   ┌────────────┐     │
│  │ relay 数据面 │    │ 边缘探测器   │   │ 后续组件…    │     │
│  │ [入口角色]   │    │ [入口/落地]  │   │            │     │
│  │ ≤10MB       │    │ ≤10MB       │   │            │     │
│  └─────┬──────┘    └────────────┘   └────────────┘     │
│        │ 数据流直连落地（不经核心/面板）                    │
│  ┌─────────────────────────────┐                       │
│  │ 被管代理进程（xray/sing-box…） │ ← 核心监管，非 agent 组件│
│  └─────────────────────────────┘                       │
└────────────────────────────────────────────────────────┘
```

## 2. 核心最小集（不变式）

| 职责 | 说明 | 对应契约 |
| --- | --- | --- |
| 注册/心跳 | 元数据（区域/运营商/成本/套餐/方向/角色）上报 + 负载聚合上报 | `hello` / `heartbeat` |
| 代理进程管理 | xray/sing-box/hysteria2 启停/重载/崩溃拉起（期望态状态机） | `proc_report` / `proc_ctl` |
| 配置接收 | sha256 校验 → 原子替换 → 失败回滚 | `config.push` / `config.ack` |
| 流量/负载上报 | 连接数/带宽/CPU/带宽利用率 | `traffic.report` / heartbeat |

- 核心不认识的组件类型不装配；组件全部缺席时核心照常工作（纯代理节点场景）。
- 心跳路径不依赖任何组件：relay 崩、探测器崩，心跳与进程管理照常——**故障隔离是硬要求**。

## 3. 角色组件规范

### 3.1 装配矩阵

| 组件 | 入口角色 | 落地角色 | 说明 |
| --- | --- | --- | --- |
| relay 数据面 | ✅ 默认 | 可选（接收入站 relay 时） | 传输插件随 relay |
| 边缘探测器 | ✅ 默认 | 可开 | 探测任务见《入口与负载均衡设计》§C.4 |
| 后续组件 | —— | —— | 按同规则接入：独立进程 + unix socket + 可缺席 |

### 3.2 组件生命周期与故障隔离

- 组件与核心**平级独立进程**，各自 systemd unit（`Restart=on-failure`），不互为父子；
- 组件崩溃只影响自身职能：探测器崩 → 该节点暂时无探测结论（其他入口的互探结论仍覆盖它）；relay 崻 → 该入口暂不可用（面板按摘挂流程切走）——**心跳与进程管理始终在线**；
- 组件不重连面板：面板↔组件的一切指令经核心中转（本机 socket），组件失联由核心在心跳里标注。

### 3.3 本机 IPC 契约

```
核心 unix socket：/run/ferry/agent.sock（未实现：当前组件为进程内角色调用，IPC v1 待定）
组件 → 核心：component.register {name, version, endpoints}（未实现，同上）
             probe.report / relay.status 等上报（核心聚合进心跳或转发面板）
核心 → 组件：本机配置文件下发（原子写 + SIGHUP 重载），指令转发（panel.* → 组件）
```

- 配置文件是组件的主配置源（核心收到 `config.push` 后落盘并通知重载），socket 只传运行态消息，避免双份状态。

## 4. 插件化口径

- **组件 = 独立二进制**（同仓库 `agent/cmd/` 下分入口），按角色选择安装与 systemd 装配——静态单文件、无运行时依赖，小内存部署友好；
- **传输插件 = 编译期接口**（接口与实现同在 `agent/internal/tunnel/`：Tunnel 单接口 + tls-camo/wstls/ssh/quic sidecar 各实现，调用方 `agent/internal/roles/relay`），不引 `.so` 动态插件——避免 glibc/版本兼容问题，换传输=换配置（见《入口与负载均衡设计》§C.2）；
- 组件与核心的契约同样是 agentproto 子集：协议版本统一演进。

## 5. 内存预算（目标值）

| 进程 | 预算 | 手段 |
| --- | --- | --- |
| 核心 | ≤10MB | 无 ORM、无 gin（agent 用轻量 HTTP/WS 栈）、心跳聚合限长 |
| relay | ≤10MB（不含并发流缓存） | 流式转发不缓冲全量、mux 上限可配 |
| 探测器 | ≤10MB | 探测任务串行小并发、结果即发即弃 |
| ferry-quic（可选 sidecar） | 不占核心预算 | quic-go 只落此独立二进制（E-18b），agent 主程序不携带、尺寸门禁（E-4）不量它；不用 QUIC 传输的部署不装（Makefile build-quic） |

- 超预算处置：配置可裁（关组件、降心跳频率），dash 节点卡展示 agent 实际内存（来自心跳）。

## 6. 目录与构建

```
agent/
├─ cmd/agent/        # 核心（现有）
├─ cmd/ferry-quic/   # QUIC 传输 sidecar（E-18b，可选发布件：make build-quic 单独构建）
├─ cmd/relayd/       # relay 数据面（未单列：当前角色库形态 agent/internal/roles/relay，独立进程为后续演进）
├─ cmd/probed/       # 边缘探测器（未单列：同上，当前进程内角色）
├─ internal/         # 共享实现（config/link/procs/host/tunnel/quictunnel/roles…）
packages/agentproto/ # 契约（组件与核心共用）
```

- `make build-agent` 产出 ferry-agent（CGO_ENABLED=0；relay/探测器为进程内角色）；QUIC 传输为独立目标 `make build-quic` 产出 ferry-quic sidecar（quic-go 只落此二进制，agent 主程序不携带，尺寸门禁 E-4 不量它）；角色部署模板只装需要的二进制。
