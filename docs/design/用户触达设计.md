# 用户触达设计（联系与断联容灾）

目标：与用户沟通易断联——面板域名被封或面板挂了时用户仍能找到我们。多通道触达统一经 Herald 投递（见《告警通道设计》），带外通道（TG bot）为核心容灾手段。

## 1. 通道矩阵

| 通道 | 形态 | 断联可用 | 阶段 |
| --- | --- | --- | --- |
| 站内信 | panel 内通知列表 | ❌（面板挂则不可见） | P1 随通知中心 |
| 邮件 | 例行+事件，经 Herald | ✅ | P1 |
| Telegram bot | 推送+交互自助 | ✅（带外核心） | P1 |
| RSS | `/feed.xml` 公告订阅 | ◐（历史公告可见） | P1 |
| 微信 / 邮件列表 | 插件位 | —— | 接 Herald 新通道即用（P2+） |

- ferry 不自建投递通道：全部经 **Herald** 分发（TG/邮件等通道实现在 Herald 侧）。

## 2. Telegram bot（推送 + 交互自助）

```
用户绑定 TG（chat_id 入库）
   ├─ 推送：到期提醒 / 流量预警 / 订单与兑换结果 / 断联新入口（见 §4）
   └─ 交互命令（bot 直答，读 ferry 服务端只读接口）：
        /flow   查剩余流量
        /expire 查到期时间
        /order  查最近订单
        /buy    购买入口（回面板链接或卡密指引）
```

- bot 后端独立部署（不依赖面板域名存活），配置面板地址与 Herald；ferry 只做对接。

## 3. 联系信息绑定

- **TG 或邮箱至少一个必填**：注册/首登引导补全，未绑定不可关闭引导；
- `user_contacts` 记录绑定与偏好；投递失败（邮件退信/TG 送达失败回执）→ 标记 `stale` 并站内提醒换绑，连续失败升级一封常规邮件/一条 bot 消息；
- 频率偏好：例行邮件可退订；**账单类默认必收**（涉及权益，只可改通道不可关）。

## 4. 断联容灾（核心）

```
正常态
  面板域名 = 唯一入口；bot/邮件/RSS 常态推送
面板域名被封 / 面板不可达
  ① TG bot（带外）不受影响 → 面板判定域名异常或人工确认 → bot 主动推「新入口」
  ② 订阅文本带备用信息 → 客户端手里始终有备用地址
  ③ 邮件侧闭环 → 域名变更即时推送新域名清单（§5）
  ④ 恢复后 RSS/站内信公告归档，全部通道回常态
```

- **订阅附带备用信息**：订阅响应附带备用公告地址与备用域名列表（`subscription-userinfo` 扩展头或订阅文本注释），客户端缓存的订阅里自带逃生通道；
- 判定口径：面板自身入口域名探测失败（复用边缘探测结论）或管理员手动标记「断联态」。

## 5. 邮件例行（调度器触发，经 Herald 投递）

| 邮件 | 周期 | 内容 | 默认 |
| --- | --- | --- | --- |
| 月账单 | 可配（默认每月） | 流量用量、套餐状态、到期时间、续费入口 + 当期节省报表亮点（《流量节省设计》§6） | **必收** |
| 域名例行 | 可配 | 当前可用入口域名 / 备用地址清单，保新鲜 | 可退订 |
| 域名变更 | 即时 | 域名切换立即推一封——断联容灾的邮件侧闭环 | 必收 |

- 数据来源：账单取用量与订单聚合；域名清单取入口域名配置（§6 `entry_domains`）；
- 周期配置在 dash；发送结果（成功/退信）回写触达记录。

## 6. 数据模型

```sql
-- 绑定与偏好（在《用户面板运营设计》notifications 之外）
CREATE TABLE user_contacts (
    user_id       INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    tg_chat_id    TEXT,
    email         TEXT,
    channel_prefs TEXT NOT NULL DEFAULT '{}',  -- {类型:{站内/邮件/tg 开关,阈值}}
    bound_at      DATETIME,
    stale         INTEGER NOT NULL DEFAULT 0   -- 失效待换绑
);

-- 入口域名与备用地址（断联容灾与域名邮件的数据源）
CREATE TABLE entry_domains (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    domain TEXT NOT NULL,
    role TEXT NOT NULL,                 -- primary/backup
    region TEXT,                        -- 适用区域，空=全区域
    enabled INTEGER NOT NULL DEFAULT 1,
    updated_at DATETIME NOT NULL
);

-- 触达任务与结果（例行+即时，经 Herald）
CREATE TABLE touch_jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    channel TEXT NOT NULL,              -- email/tg/inbox/rss
    kind TEXT NOT NULL,                 -- bill/domains/expire/quota/notice
    payload TEXT NOT NULL,              -- 渲染内容或参数
    status TEXT NOT NULL DEFAULT 'pending', -- pending/sent/failed
    sent_at DATETIME,
    error TEXT,
    created_at DATETIME NOT NULL
);
CREATE INDEX idx_touch_jobs_due ON touch_jobs(status, created_at);
```

## 7. 分期

| 阶段 | 内容 |
| --- | --- |
| P1 | 绑定必填与换绑、RSS 公告输出、月账单与域名例行邮件（调度器→Herald）、TG bot 推送+交互、断联容灾（带外 bot/订阅备用信息/推新入口） |
| P2+ | 微信/邮件列表等新通道（接 Herald 即用） |

---

> 合规定位：ferry 是代理集群管理工具，部署与运营的合规责任在部署者（见《合规定位声明》）。
