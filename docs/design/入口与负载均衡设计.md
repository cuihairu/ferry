# 入口与负载均衡设计

目标：入口池经 relay 隧道接落地池的双向拓扑——**出海线**（国内入口 → 海外落地）与**回国线**（海外入口 → 国内落地，回国加速）共用同一套架构，按方向标签分流；入口与落地都是 agent 节点，角色可配；故障按区域/运营商聚合处置；分配在健康与负载之外做成本感知与带宽容量约束。探测下沉到边缘（入口 agent 探测），面板只收探测结论做决策，不集中探测（单点假死、网络视角失真）。

全文分两篇：**篇一·出海线**（重点：伪装与抗封）、**篇二·回国线**（重点：线路与回程质量），共享设施（架构/元数据/隧道/探测/分配/数据模型）归入「共享篇」。

## 0. 双向拓扑总则（两篇共用）

```
出海线（篇一）：客户端 → 国内入口池 ─relay 隧道→ 海外落地池 → 公网
回国线（篇二）：海外入口池 ─relay 隧道→ 国内落地池 → 国内目标
```

- **拓扑方向无关**：节点只换 `direction` 标签（`out` 出海 / `in` 回国 / `both`）与侧重，agent 架构、隧道、探测、分配、摘挂、数据模型全部同一套。
- `role` 可配：`entry` / `landing` / `both`；面板机不装 agent。
- relay 方向：落地开监听，入口主动拨出（agent 只出站的原则不破）；客户端到入口为正常代理端口（由被管代理进程监听）。

## 篇一 · 出海线（国内 → 海外，重点：伪装与抗封）

### 1.1 拓扑

```
客户端
  │  订阅下发入口列表 + 测速信息，客户端选优
  ▼
国内入口池（entry 角色，多 IP/多机房，按区域分组）
  │  relay 隧道（传输插件：TLS 伪装默认 / QUIC / WS-TLS，SSH 备选）
  ▼
海外落地池（landing 角色）
  ▼
公网目标
```

### 1.2 传输选型原则：抗封 = 长得像主流协议

| 传输插件 | 伪装对象 | 默认 | 说明 |
| --- | --- | --- | --- |
| TLS 伪装（trojan / vless-xtls 系） | HTTPS | ✅ 默认 | 443 端口 TLS 握手，与正常 HTTPS 同形 |
| QUIC（hysteria2 系） | HTTP/3 | 二段 | UDP 443，与 HTTP/3 同形 |
| WS-TLS | HTTPS + WebSocket | 二段 | 云 CDN 前可作入口伪装 |
| SSH | SSH 协议 | 备选 | 特征独特易被识别，不作默认 |
| 自定义裸 UDP | —— | 不做 | 无伪装价值，特征独特 |

- 裸 SSH 与自定义裸 UDP 特征独特、易被识别，只作备选不作默认。
- 节点按传输类型标注（`nodes.transport`），切换传输 = 换配置不改架构（隧道层不动，只换 Transport 实现，接口见共享篇 §C.2）。
- 某区域用哪种传输由该区域的探测结果决定（哪种活着用哪种），见共享篇 §C.4。

### 1.3 入口选择（客户端侧）

- 订阅下发入口列表 + 测速信息：clash 输出按区域分组的策略组（url-test 组内自选优），v2ray 分享链接按区域分组、备注带面板聚合的测速延迟；测速数据来自边缘探测结论，面板聚合后随订阅输出。
- 客户端选优：客户端在组内自行选延迟最低入口（url-test/手选），面板不下发死入口。
- 预留智能 DNS 分地域（P2）：按客户端解析来源地域返回就近区域入口，订阅域名留分地域解析位。

### 1.4 探测侧重（出海）

- 出口基线（入口 → 公网直连）区分「隧道问题」与「本机/本地网问题」；
- 入口被封检测（其他入口互探拨代理端口）——出海线的被封恢复流水线见《计划扩充设计》。

## 篇二 · 回国线（海外 → 国内，重点：线路与回程质量）

### 2.1 拓扑

```
海外客户端 / 海外入口池（entry 角色，direction=in）
  │  relay 隧道（同一套传输插件抽象）
  ▼
国内落地池（landing 角色，direction=in）
  ▼
国内目标（回程质量即体验）
```

- 架构与出海线完全同一套，只换方向：海外入口 → 国内落地 = 回国加速。

### 2.2 线路类型（`nodes.line_type`）

| 取值 | 说明 | 定位 |
| --- | --- | --- |
| `cn2_gia` | 电信 CN2 GIA 优质回国线 | 电信回程优 |
| `cu_vip` | 联通 VIP 优质线 | 联通回程优 |
| `cmi` | 移动 CMI | 移动回程 |
| `iplc` | IPLC 专线 | 免绕、低延迟，成本最高 |
| `163` | 163 骨干（普通线） | 性价比，晚高峰易拥塞 |
| `普通` | 未标注/未知 | 默认 |

- 回国线的体验差异在回程线路，不在伪装——与出海线的抗封重点正交。
- 线路类型必填（可标「普通」），dash 录入可改，与 `direction` 一起构成方向分流的依据。

### 2.3 回国探测器

- 海外入口的边缘探测器对国内落地做**回程探测**：延迟/丢包/连通，复用 `probe.report` 链路（target_kind=`tunnel`，direction=in）。
- 探测周期在晚高峰（19:00–23:00）加密——回国体验全在晚高峰，白天数据没有代表性。

### 2.4 晚高峰报表（dash）

- 按小时分段的回程质量报表；**晚高峰时段（19–23 时）单独出报表**：该时段的平均延迟/丢包/可用率，与平峰对比。
- 报表数据源 = `probe_reports` 按小时聚合，随成本看板同页展示，供选线路与切流决策。

### 2.5 回国分配侧重

- 回国流量优先优质线路节点（`cn2_gia`/`cu_vip`/`iplc`），**成本容忍度高**——晚高峰不拥塞比省几块钱重要；`163` 普通线走量与兜底。

## 共享篇（两篇通用）

### C.1 agent 架构（核心 + 角色组件）

agent 拆「核心 + 角色组件」，核心恒定最小集，组件按节点角色装配、独立进程、可插拔。

```
┌─ 节点主机 ────────────────────────────────────────┐
│                                                    │
│  agent 核心（常驻，目标 ≤10MB 内存）                  │
│   ├─ 注册/心跳（区域/运营商/成本/套餐/方向元数据）      │
│   ├─ 代理进程管理（xray/sing-box… 启停/重载/崩溃拉起） │
│   ├─ 配置接收（校验 → 原子替换 → 失败回滚）            │
│   └─ 流量/负载上报（连接数/带宽/CPU）                  │
│                                                    │
│  角色组件（按角色装配，独立进程，可插拔）                │
│   ├─ relay 数据面      [入口]   ← 传输插件随 relay     │
│   ├─ 边缘探测器        [入口/落地 可开]                │
│   └─ 预留…（后续组件按同规则接入）                      │
│                                                    │
│  交互：本机 IPC（unix socket）+ 配置文件，仅此两条       │
└────────────────────────────────────────────────────┘
```

- 角色落地：入口节点 = 核心 + relay + 探测器；落地节点 = 核心（+ 探测器）；面板机不装 agent。
- 故障隔离：relay 崩不带崩核心心跳，探测器崩不丢进程管理——组件独立进程，互不共享生命周期。
- 核心与组件的契约也是 agentproto 的子集：组件向核心注册本机端点/状态，核心统一随心跳上报面板；组件不直连面板。

### C.2 中转隧道：传输插件抽象

统一隧道接口与传输解耦：隧道层管生命周期，传输插件只管「字节流怎么伪装」。

```go
// relay 内部契约（packages/ 内共享类型，实现放 agent/internal/relay）
// Tunnel 提供隧道生命周期：多路复用、心跳、重连对上层透明。
type Tunnel interface {
    // Start 建立到落地的隧道并保活（内含重连退避）。
    Start(ctx context.Context) error
    // Open 打开一条到目标的流（多路复用）。
    Open(ctx context.Context, target string) (Stream, error)
    Close() error
}

// Transport 是传输插件：拨号与伪装，不含隧道逻辑。
type Transport interface {
    Name() string // tls / quic / ws-tls / ssh
    // Dial 建立一条到落地的伪装连接。
    Dial(ctx context.Context, addr string) (net.Conn, error)
}
```

### C.3 注册元数据（agentproto 契约扩展）

agent 注册（`hello`）必须携带元数据；配置文件填写为初值，注册时上报，面板可改（以面板为准，改后经 `hello_ack` 同步回 agent）。

| 字段 | 必填 | 取值 | 用途 |
| --- | --- | --- | --- |
| `role` | 是 | entry / landing / both | 池归属与组件装配 |
| `direction` | 是 | out 出海 / in 回国 / both 双向 | 方向分流（篇二 §2.2） |
| `line_type` | 是 | cn2_gia/cu_vip/cmi/iplc/163/普通 | 回国线路质量（篇二） |
| `region` | 是 | 区域名（如 华东），可「未知」 | 故障聚合维度 |
| `city` | 否 | 城市 | 展示与细分 |
| `datacenter` | 否 | 机房标识 | 多机房入口管理 |
| `isp` | **是** | 电信/联通/移动/教育网/…，可标「未知」但不许空 | 故障聚合维度 |
| `labels` | 否 | 自定义标签数组 | 灵活标记（如 bgp、tea） |
| `transport` | 是 | tls / quic / ws-tls / ssh | 传输标注 |
| `billing_type` | **是** | 按流量 / 包月 / 固定带宽 | 成本口径（§C.6） |
| `traffic_price` | 否 | 流量单价（分/GB） | 成本计算 |
| `monthly_cost` | 否 | 月固定成本（分/月） | 成本看板 |
| `currency` | 否 | 币种，默认 CNY | 成本换算 |
| `cost_note` | 否 | 备注 | 人工记录 |
| `bw_up_mbps` | **是** | 套餐上行带宽（Mbps；国内 3M/5M 这类小带宽必须如实填） | 容量权重、利用率 |
| `bw_down_mbps` | **是** | 套餐下行带宽（Mbps） | 容量权重、利用率 |
| `monthly_traffic_quota` | 否 | 月流量配额（字节，0=不限） | 套餐展示与封顶 |
| `rate_limited` | 是 | 是否限速 | 套餐规格 |
| `burst` | 否 | 是否峰值突发 | 套餐规格 |

**套餐带宽校准**：agent 注册后跑一次轻量测速，实测容量与套餐上报值偏差大（如超过 ±30%）时以实测为准，记录实测容量与校准时间；分配的容量权重与负载利用率的分母都用校准后容量。

**故障按区域聚合**：同区域多节点同时异常 = 判定「区域故障」，处置是整区域切走（订阅换区域入口 / 落地重分配），不是逐个摘挂——区域断网时逐个摘既拖时间，又会把区域内好节点误杀。**运营商同为聚合维度**：某运营商链路抖 = 运营商级故障，同 ISP 节点一起切。告警按区域/运营商聚合发（「XX 区域入口整体不可达」而非 N 条单点告警），区域判定逻辑在面板侧聚合。

### C.4 健康探测与故障处置

#### C.4.1 探测职责在入口节点

探测下沉到边缘：各入口 agent 的探测器负责探测，面板只收结论。面板集中探测的问题：单点假死把全网判死、单一网络视角失真（面板所在地与客户端所在地可达性不同）。

#### C.4.2 探测类型（边缘探测器组件）

| 类型 | 谁探 | 探什么 |
| --- | --- | --- |
| 隧道探测 | 入口 → 落地 | 经 relay 的连通/延迟/丢包（双向通用；回国线见篇二 §2.3） |
| 出口基线 | 入口 → 公网 | 直连基线，区分「隧道问题」与「本机/本地网问题」 |
| 入口被封检测 | 其他入口互探 | 从外部视角拨该入口的代理端口，判可达/被封 |
| 落地健康 | 入口 → 落地 | 落地端口与出口可达性 |

- 探测器周期执行，上报 `probe.report`（目标、rtt、丢包、可达、被封、判定、区域/运营商快照）；面板只收结论做决策，不集中探测。

#### C.4.3 聚合判定与摘挂

- 单点摘挂（P1）：目标连续 N 次 sick → 摘除；恢复 M 次 → 复位。
- **区域聚合（P0）**：窗口 T 内同区域异常节点数 ≥ N 或占比 ≥ X% → 判区域故障 → 整区域切走（订阅换区域入口、该区域落地重分配），窗口结束后恢复再切回；不逐个摘挂。
- **运营商聚合（P0）**：同 ISP 跨区域节点一起 sick → 运营商级故障，同 ISP 一起切。
- 告警按区域/运营商合并发（一个区域一条），dash 按区域给状态灯。
- 热更新换线：摘挂结论 → 面板配置推送变更入口/落地列表 → agent 校验重载（复用 config.push 链路）→ 入口池补位；被封后的自动恢复流水线见《计划扩充设计》。

#### C.4.4 探测结果决定传输

某区域的各传输探测结论决定该区域用哪种传输（哪种活着用哪种）；面板按区域下发 `transport` 标注与对应配置，切换传输 = 换配置不改架构。

### C.5 落地分配（面板侧）

#### C.5.1 负载信号

agent 心跳上报负载：连接数、带宽（rx/tx 速率）、CPU、内存、**带宽利用率**（实测吞吐 / 校准后套餐带宽）——P0 先有连接数与带宽两项，利用率随自动均衡补。

#### C.5.2 分配策略

- **方向分流（前置）**：先按 `direction` 选池——出海流量在出海池内选，回国流量在回国池内选，两池策略侧重不同（篇二 §2.5：回国优先优质线路、成本容忍高；出海走性价比）。
- **P0 手动分配**：dash 上为入口/区域手动指定落地列表与权重，经配置推送生效。
- **P1 自动均衡：加权最小连接**——权重由「健康度 + 当前连接数 + 带宽容量 + 线路档（回国线）+ 成本档」合成，新连接分给当前权重最优的落地；**带宽作容量权重**：3M 小带宽节点按容量少分新连接，不把小水管灌爆；低峰窗口做再平衡（新连接切到目标节点、存量连接排空，不硬断）。
- **成本感知（P1 随自动均衡落地）**：
  1. 同等健康与负载条件下优先低成本节点；
  2. 成本权重三档可配：成本优先 / 性能优先 / 均衡；
  3. 流量成本高的节点少分新连接，高成本节点留作备用/溢出。
- **计费口径**：仅「按流量计费」的节点参与成本优先判定与流量成本告警；包月 / 固定带宽 / 不限流量的节点不参与流量成本逻辑（固定带宽套餐即包月口径；月固定成本只进成本看板汇总，不影响分配）。`billing_type` 必填。

#### C.5.3 成本看板与告警（P1）

- 各节点流量花费（流量 × 单价，按计费方式分列）；
- 区域 / 运营商维度成本汇总；
- 月度成本预估（按当前流量推算）；
- 高成本告警：某节点流量费用超阈值，提示切流（面板发，按节点单发）。

#### C.5.4 成本参考库（插件位，P2）

- **手录成本为准**：`nodes` 上的单价/月固定成本是分配与看板的唯一权威来源。
- 参考价来源做成插件位 `costref.Source`（接口：按机型/区域取参考价），先落设计后接实现：
  - 海外：接开源比价数据（infracost 类云价格库、公开价格表），给出同配置牌价对比——「手录价 vs 牌价」偏差提示；
  - 国内：价格页变动提醒——关注条件（机房 / 配置 / 价位）命中的降价或促销进 dash 通知。
- 参考价只做提示不自动改手录价，避免脏数据影响分配。

### C.6 数据模型

```sql
-- nodes 表扩展（ensureColumns 增量迁移）
direction        TEXT    NOT NULL DEFAULT 'out',   -- out 出海/in 回国/both 双向
line_type        TEXT    NOT NULL DEFAULT '普通',   -- cn2_gia/cu_vip/cmi/iplc/163/普通
role             TEXT    NOT NULL DEFAULT 'landing',  -- entry/landing/both
region           TEXT    NOT NULL DEFAULT '未知',
city             TEXT,
datacenter       TEXT,
isp              TEXT    NOT NULL DEFAULT '未知',      -- 必填，可「未知」不可空
labels           TEXT    NOT NULL DEFAULT '[]',       -- JSON 数组
transport        TEXT    NOT NULL DEFAULT 'tls',      -- tls/quic/ws-tls/ssh
billing_type     TEXT    NOT NULL DEFAULT '包月',      -- 按流量/包月/固定带宽（必填）
traffic_price_cents INTEGER NOT NULL DEFAULT 0,       -- 分/GB，仅按流量计费有意义
monthly_cost_cents   INTEGER NOT NULL DEFAULT 0,      -- 分/月
currency         TEXT    NOT NULL DEFAULT 'CNY',
cost_note        TEXT,
bw_up_mbps       INTEGER NOT NULL DEFAULT 0,        -- 套餐上行 Mbps，必填（0=未填不合法）
bw_down_mbps     INTEGER NOT NULL DEFAULT 0,        -- 套餐下行 Mbps，必填
monthly_traffic_quota_bytes INTEGER NOT NULL DEFAULT 0, -- 月流量配额，0=不限
rate_limited     INTEGER NOT NULL DEFAULT 1,        -- 是否限速
burst            INTEGER NOT NULL DEFAULT 0,        -- 是否峰值突发
speed_measured_mbps      INTEGER,                   -- 测速校准实测容量（偏差大以实测为准）
speed_calibrated_at      DATETIME,

-- 落地分配记录（入口池/落地池 = nodes.role 分组，不另建池表）
CREATE TABLE landing_assignments (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    entry_node_id    INTEGER,               -- 入口节点（空=区域级分配）
    landing_node_id  INTEGER NOT NULL,
    direction        TEXT    NOT NULL,      -- out/in，方向分流留痕
    strategy         TEXT    NOT NULL,      -- manual/least_conn/cost_first/perf_first/balanced
    weight           INTEGER NOT NULL DEFAULT 0,
    reason           TEXT,                  -- region_fault/failover/manual...
    assigned_at      DATETIME NOT NULL,
    released_at      DATETIME,              -- 空=生效中
    release_reason   TEXT
);

-- 探测历史（边缘探测器上报，面板存证并做聚合）
CREATE TABLE probe_reports (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    node_id        INTEGER NOT NULL,        -- 探测者（入口 agent）
    target_kind    TEXT    NOT NULL,        -- tunnel/exit/peer
    target_node_id INTEGER,                 -- 目标节点（隧道/互探）
    target_host    TEXT,                    -- 出口探测目标
    direction      TEXT    NOT NULL DEFAULT 'out', -- 探测方向（回国回程报表按此过滤）
    rtt_ms         INTEGER,
    loss_pct       INTEGER,                 -- 0-100
    reachable      INTEGER NOT NULL,
    blocked        INTEGER NOT NULL DEFAULT 0,
    verdict        TEXT    NOT NULL,        -- healthy/sick
    region         TEXT    NOT NULL,        -- 目标区域快照（聚合用）
    isp            TEXT    NOT NULL,        -- 目标运营商快照
    probed_at      DATETIME NOT NULL
);
CREATE INDEX idx_probe_window ON probe_reports(target_kind, target_node_id, probed_at);

-- 区域/运营商状态灯（聚合判定的落库结果，dash 直接读）
CREATE TABLE dimension_status (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    scope      TEXT    NOT NULL,            -- region/isp
    key        TEXT    NOT NULL,            -- 华东/电信
    state      TEXT    NOT NULL,            -- healthy/degraded/failed
    reason     TEXT,
    since      DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    UNIQUE(scope, key)
);
```

### C.7 管理面（dash）

- 节点视图：按区域分组 + 区域级状态灯；入口/落地分组视图；按运营商视角切换（区域灯/ISP 灯同构）；方向标签（出海/回国）与线路类型列。
- 节点卡：展示套餐（带宽/月流量/限速/突发）与当前带宽利用率，利用率超 80% 预警提示。
- 负载看板：各节点连接数/带宽/CPU，入口与落地分列。
- 回国晚高峰报表（篇二 §2.4）。
- 手动调配：手动指定落地分配、手动摘除/恢复、强制切区域（P0 先给手动分配与手动摘除）。
- 成本看板（P1）：节点流量花费、区域/运营商汇总、月度预估；成本参考库提示（P2）。
