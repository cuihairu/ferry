# 决策记录（代决关闭项）

只登记**已代决关闭**的扩充项：判断「现在不做」并给出被否选项与重开触发条件。
凭据/商户资质、上游发布、真机环境、复现观察类外部等待项不在此列——仍挂
`todo.md` 的 `[BLOCKED]` 行，等外部材料到位再开。

代决授权边界（2026-10-14）：设计/需求类可自行代决；**版本号/发版、License 变更、
付费采购、素材授权**四类留用户，不进本表。

## 1. mTLS CA 编排：不建编排，维持手签脚本

- **方案**：面板侧不做 CA 编排。自签 CA 与按节点签发维持 `deploy/mtls-ca.sh init|issue`
  两步手工；agent 侧三件套经 TLSConfig 声明（`agent/internal/config/config.go:15-18`，
  全部为空时仅节点令牌走系统根证书校验），安装脚本 `--ca/--cert/--key` 传入
  （`deploy/README.md`「mTLS 证书生成」节）。
- **被否选项**：面板内自动签发 + 到期轮换编排——需新增 CA 私钥管理面、到期提醒、
  批量重签与吊销同步，是纯前置成本。
- **理由**：mTLS 消费方为零（默认关闭），编排对象不存在；节点规模未达「手工签发
  不可维持」的量级（每节点两条命令）。
- **重开触发**：mTLS 消费方 ≥1 且节点数使手工签发不可维持，或用户点名。

## 2. 调度历史权重自动调参：不做，维持人工配置

- **方案**：不做基于历史负载的权重自动漂移；权重维持人工配置——权重口径见
  《调度核心设计》§1「采集维度 → 决策权重映射表」（每个采集字段对应一个权重），
  当前由面板侧人工给定。
- **被否选项**：历史延迟/失败驱动的自动权重更新（含回滚策略与「人工覆盖优先序」
  设计）——工程量集中在算法校准，不是功能价值。
- **理由**：单站规模人工调参已满足；自动调参需要历史分布与真实故障样本，当前无
  数据可校准，误调比不调更糟。
- **重开触发**：多机放量且人工调参出现瓶颈，或用户点名。

## 3. 节点级流量预算与告警百分比：不做，维持用户级配额

- **方案**：不做 per-node 预算与百分比告警；维持用户级月流量配额
  （`server/internal/storage/models.go:94` MonthlyTrafficQuotaBytes）与节点流量
  记账现状。
- **被否选项**：节点预算阈值 + 百分比告警——新增告警通道负载与阈值调参面。
- **理由**：单站规模下节点总量与流量在 dash 节点列表已可见；无对应的告警疲劳或
  成本诉求，先行实现只会产出噪音告警。
- **重开触发**：多机部署出现且需要节点级预算约束，或用户点名。
